这些来源均为第三方目录，不作为本站对品牌官方身份的认证。软件覆盖偏重 macOS 生态，不能据此认为软件支持所有系统。机构数据可能保留旧名称、旧地址或不准确的信息，不表示办学资质认证。地区筛选使用来源记录的机构所在地；GLOBAL 表示未限定或涉及多个地区，不承诺当地可访问或可购买。

ROR 由 Research Organization Registry 发布。本次使用 2026-09-22 的 v2.13 固定快照，取 active 且类型包含 education 的机构，只采用明确列出的 HTTPS website 链接。名称优先采用上游中文 label，其他名称保留为别名；未自行翻译、生成或补猜网址。1,771 条新增机构记录的所在地为 CN。

ROR 元数据遵循 CC0；地区代码源自 [GeoNames](https://www.geonames.org)，遵循 [CC BY 4.0](https://creativecommons.org/licenses/by/4.0/)。我们只保留国家/地区代码，省市、坐标及其他位置字段均省略。归属说明和两份许可原文随页面与导出数据提供。

`sourced` 记录在默认搜索中可见，但只有资料页和来源链接，不提供直达，不参与已核对主机名匹配。只有另行完成主体与入口关系核对才能进入 `verified`。采集日期与核验日期分开，不生成“可信分数”。

## 过滤与去重

软件/Hipo 原始快照有 7,769 个 cask 和 10,268 个高校记录，计数保存在 `sources.json`；ROR 原始快照有 141,528 条机构记录，计数保存在 `ror-source.json`。每行最多计一个排除原因，按脚本的检查顺序归类。

- 仅采用来源明确登记的 HTTPS 首页，不从名称猜测网址，也不把 HTTP 自动改写为 HTTPS。
- 排除无效网址、查询参数、锚点、凭据、自定义端口、IP 地址和示例域名。
- 排除 Homebrew 停用/弃用项目、字体包、带版本或预览标记的变体。
- 一个高校只收录来源中的第一个可用 HTTPS 首页，不把多个域名算成多个学校。
- 按主机名和路径去重，忽略协议、前导 www 和尾部斜杠；路径大小写仍有意义。该规则仅用于去重，绝不用于判断官网身份。
- 人工维护的首页或同名软件优先保留。相同主机名下不同产品路径仍可分别收录；记录数与独立主机名数分别报告。
- ROR 与所有既有来源交叉去重，另按同一地区内的名称/别名去重；不把 Wikipedia 链接或 domains 字段推导成网站。稳定 ROR ID 保留为本地 ID，网址变更不会自动算作新增机构。

HTTPS 是这一批数据的筛选条件，不是安全、真实性或可达性证明。过滤后每条仍然需要独立复核。被排除的 HTTP 或旧版本数据不能据此判定为假网站。

## 可追溯字段

`data/imported/catalog.json` 和 `ror.json` 是生成文件。Homebrew 使用 API 返回的 `tap_git_head` 和 `ruby_source_path`，Hipo 使用固定 Git 提交；ROR 同时保留机构页面和固定 Zenodo 发布快照，明确说明机构页面可能后续更新。两个来源清单各自记录 SHA-256、源版本、许可证、采集日期与过滤统计，构建时合并导出。

仓库保存规范化结果，不复制安装包、上游代码或整个上游仓库。许可证原文位于 `data/licenses/`，静态构建会将许可证与导出文件一起发布。数据中的品牌名与商标不表示授权或背书。

## 更新来源

依赖只需安装一次；正常构建和测试不联网获取目录，使用仓库内快照。

```sh
npm ci --ignore-scripts
npm run import:data -- --refresh
npm test
npm run audit:data
npm run build
git diff --stat
```

`--refresh` 才会下载最新来源。下载、结构校验、去重、人工修订检查全部完成后才写入文件。导入不足 2,000 条或数量减少超过 20% 时默认中止；确认源范围发生合理变化后才使用 `--allow-large-drop`。导入命令不会自动提交、推送或发布。

Homebrew 在线 API 是滚动内容；无法只凭一次 API URL 重新得到历史字节。要精确复现某次导入，请另存原始响应，并核对清单中的 SHA-256，再离线重放：

```sh
node scripts/import-data.js --casks /path/cask.json --universities /path/universities.json --university-revision <40位提交SHA> --date 2026-09-30
```

这里的 revision 必须对应保存的高校文件，date 必须是实际采集日期。脚本会重新计算哈希，审阅者应与预期快照比较，不会把用户提供的文件当成已核验官网。

ROR 作为独立批次更新，不随软件/Hipo 刷新被覆盖。下载 [固定发布包](https://zenodo.org/records/22902037/files/v2.13-2026-09-22-ror-data.zip)，核对上游 MD5 `a935217de21e7983b977f5419f1a6b20` 后解压 JSON。该 JSON 的 SHA-256 为 `6d032ff473f771e015da0837fe28b881a8f85822ee7815effefe11dc49c4346c`：

```sh
node scripts/import-ror.js --file /path/v2.13-2026-09-22-ror-data.json --snapshot https://zenodo.org/records/22902037 --sha256 6d032ff473f771e015da0837fe28b881a8f85822ee7815effefe11dc49c4346c --date 2026-09-30
```

哈希不一致、缺失人工修订对应记录、ROR 批次少于 10,000 条，或后续批次数量下降超过 20% 都会中止，不写入结果。ROR 导入脚本只读取指定 JSON，不请求机构网页；构建和测试也不需要下载约 318 MB 的原始 JSON。它不会覆盖其他来源批次，重复执行同一快照不增加数量。两个导入命令均支持 `--dry-run`，完成校验并打印差异后不写入文件。软件名称去重排除机构来源的简称，避免把高校缩写当成同名软件而误删原有记录。

批次清单保存基线数量和排序后 ID 的 SHA-256；质量审计验证原有 4,943 个 ID 完整保留、新增量不少于 10,000。未来有意增删基线时，应在数据评审中同步更新该批次基线与相关测试，不要绕过校验把删除量隐藏在新增总量中。

## 保留人工修订

`data/overrides.json` 以导入 ID 为键，可修改 `aliases`、`name`、`description`、`tags`，或将状态降为 `pending`、`review`、`withdrawn`。别名列表为替换语义，添加新别名时保留需要的上游别名。现有 56 条中文名称或说明即通过此文件维护。

覆盖文件禁止授予 `verified`，也禁止改写原始来源与目标网址。如果需要修改网址、分类或核验状态，把该记录移入适当的 `data/sites/<category>.yaml`，保留 ID，补齐完整字段及证据。人工记录优先，下一次导入会跳过对应首页。来源删除了一个有人工覆盖的记录时，刷新会中止并提示先将它保存在人工目录，避免悄悄丢失修订。

从来源删除并不意味着网站身份失效；从来源新增也不意味着已经核验。评审应关注上游名称变化、网址迁移、错误纠正以及是否仍适合收录。

## 质量与运行成本

`npm run audit:data` 校验字段、记录最低数量、首页去重，汇总状态/分类/地区/来源，并运行本地搜索基准。报告保存到 `.reports/quality.json`，CI 上传为 `catalog-quality` artifact。搜索耗时与运行环境有关，不承诺所有设备相同。

浏览器每页 24 条；无脚本分类页每页 60 条；首页不嵌入完整目录。完整搜索索引约 7.9 MB（未压缩），保留输入防抖和中文输入法处理。搜索缓存已归一化的名称、域名和说明，避免每次输入重复解析两万多个网址。索引对象加载后视为不可变；替换数据时创建新对象，使缓存自动失效。测试检查总载荷和每条记录体积、分页结果完整性、状态与主机名核验边界。

常规链接巡检仍只处理已核对的 14 个明确入口，不会把数千条来源记录自动变成可用性或身份认证结论。批量网站连通性尚未逐站检查。
