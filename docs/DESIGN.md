# 官网收录：数据规则与维护流程

## 目标与当前范围

让用户找到正确的官网、下载或文档入口，并知道收录判断的依据。继续使用 YAML、Node.js 静态构建和 GitHub 审核流程。

2026-09-30 保留原有 62 条产品记录，其中 5 条补充了公开来源辅助核对，覆盖 14 个入口。其余候选尚未重新核验，不进入默认搜索。银行、政务等类别保留候选资料，扩充前先完成相应主体与入口的复核。

## 核验与连接检测分开

| 状态 | 含义 | 展示规则 |
| --- | --- | --- |
| pending | 尚未完成来源核对 | 仅候选清单或主动勾选后可见，无直达 |
| verified | 依据完整且在复核期限内 | 默认搜索和已核对入口 |
| review | 存在疑问或复核期限已过 | 无直达，等待维护者复核 |
| withdrawn | 判断撤销 | 不进入搜索，保留详情与 Git 历史 |

到期判断：`review_due_at` 当天仍有效，之后进入待复核。构建和浏览器搜索均判断日期，默认分支每日构建刷新静态详情。离线、禁用脚本或未及时发布时，静态内容可能滞后，应以页面的核对和复核日期为准。

连接检测只反映某节点某时刻的网络结果，不更新身份核验时间，不自动把异常记录撤销。发现异常后，维护者根据证据修改 `verification_status`。

## 什么可以成为依据

记录已确认主体、官方项目仓库、官方发布或产品页面怎样指向所收录入口。优先交叉核对组织、产品和入口之间的关系，避免仅凭同名账号、域名外观或页面自称官网得出结论。

ICP 备案、TLS 证书、域名年龄和搜索排名可以辅助调查，但单独使用不足以证明某个产品入口的归属。不要把普通网页可访问性当作身份核验。

每条证据包含原始 URL、来源标题、关系说明，以及覆盖哪些入口。多个来源是否独立需要审核人判断，不使用简单计数生成“可信分数”。

`review_method: assisted` 表示由工具或 AI 辅助核对公开来源，必须如实填写记录者；不能伪装成维护者已完成的人工审核。维护者实际复核后，可更新为 `human` 并填写自己的名字与日期。

## 数据格式

一个产品对应多个明确入口。原有 `domains` 字段已移除；宽泛的父域名列表不能充当官方入口白名单。

```yaml
- id: example-product
  name: 示例产品
  url: https://product.example.org
  description: 示例说明，请勿直接用于真实核验。
  aliases: [示例]
  verification_status: pending
```

完成核对后，需要增加以下字段（下面仅说明结构，不是实际已核验记录）：

```yaml
owner: 归属主体
verification_status: verified
review_method: human # 或 assisted
reviewer: 实际核对者
verified_at: '2026-09-30'
review_due_at: '2026-12-29'
entries:
  - id: home
    purpose: home
    label: 官网首页
    url: https://product.example.org
    region: 全球
    language: zh-CN
evidence:
  - url: https://organization.example.org/products
    title: 主体的产品介绍
    relation: 说明来源中哪个位置链接到了上面的产品入口。
    entry_ids: [home]
```

`purpose` 支持 `home`、`download`、`docs`、`login`、`source`。每个入口必须有唯一 ID，并至少被一条证据覆盖。源码托管平台等共享主机名只能说明入口托管位置，不能将该平台上的其他路径一并视为官方内容。

首页 URL 不含查询参数或锚点；具体入口可以保留业务必需参数，但审核时需要删除推广和跟踪参数。禁止凭据 URL、自定义端口、本机或私网地址。

## 搜索与网址比对

1. 无显式协议时，完整产品名或别名优先作为搜索，因此 `Node.js` 不会误进网址检查。
2. `https://node.js` 明确按网址处理，不能因产品名称相似而视为 Node.js 官网。
3. 搜索支持别名、拼音和首字母，保留下载、文档等用途信息，优先选择相应用途的入口。
4. 主机名比对精确到已登记的完整 hostname，不移除 `www`，不自动覆盖子域名。
5. 相似名字只作为导航提示，不声称已经识别仿冒或完成安全检测。
6. 默认排除候选、撤销和过期记录；候选搜索不提供外部直达按钮。

解析只使用输入的主机名，不请求用户粘贴的网址。输入不写入页面 URL、访问历史或远端统计。

## 收录与复核流程

提交候选 → 填写主体与入口用途 → 记录原始证据 → 执行数据校验 → 维护者审阅 PR → 合并 → 按部署配置发布。

对高风险类别建议安排两名维护者复核。当前仓库未强制双人审批，不能将该建议描述成已经执行的制度。需要时再通过 GitHub 的分支规则落实。

复核期限初始设为 90 天。更改入口 URL、主体或来源关系时，应重新核对并更新日期；不能只改 URL 后保留旧证据说明。Issue 不是自动发布通道。

## 巡检流程

只检查登记为 verified 的入口；即使核验到期，仍可继续记录连接情况，同时加入身份复核提醒。

检测结果保存 URL、最终 URL、重定向链、UTC 时间、节点说明和连续失败计数。计数绑定入口 ID、URL 和节点环境，更换入口或节点后从第一次开始计数。

未知域名重定向、不安全 URL、HTTPS 降级立即进入复核；网络失败、403、404 等连续两次才进入复核。检测器不会请求未知跳转目标，也不会读取完整页面或下载文件。

DNS 解析后检查所有返回地址；实际连接固定使用这些已检查地址。私网、回环、链路本地及保留地址会被拒绝，每一跳重复此规则。

跨次运行的状态保存于 Actions 缓存，本地运行保存在 `.monitor/state.json`。缓存不是永久数据库：被清理后重新积累计数。每次完整报告作为 artifact 保存，维护者可下载追溯。

Issue 提醒需要 `ENABLE_MONITOR_ISSUES=true`；使用一个汇总 Issue，根据实际 Issue 中的异常摘要去重。失败后下一次可重试；恢复后关闭，新增异常时再创建。默认只产出报告。

## 发布与维护边界

所有分支运行 CI，只有默认分支且 `ENABLE_PAGES=true` 才部署。正式构建要求真实 HTTPS `SITE_URL`，支持项目子路径。未配置时本地预览不生成示例域名的 canonical。

该版本不创建商家认领、用户系统或数据库。先用真实查找任务测试完成率、耗时、未命中需求和每条数据的维护成本。浏览器扩展和对外 API 等到核验流程与匹配规则稳定后再考虑。

现有内容和源代码公开可审阅，但尚未选择许可证。正式开放复用前应分别确定代码与数据许可。
