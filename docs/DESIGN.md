# 官网收录 · 项目构思与实现方案

## 1. 要解决的问题

在搜索引擎里搜“XX官网”，经常找不到真正的官网，原因大致有：

| 问题 | 例子 |
| --- | --- |
| 竞价广告排在前面 | 搜“WPS 下载”，前几条是带捆绑安装的下载站 |
| 仿冒 / 钓鱼网站 | `12306-xx.com`、`icbc-xx.cn` 这类假网站骗取账号和付款 |
| SEO 聚合页、内容农场 | “XX官网入口大全”页面里塞满广告和跳转 |
| 官网有多个域名或改过域名 | `qq.com` / `im.qq.com`、飞书 / Lark，普通用户难以判断 |
| 用户不会辨别 | 不知道看域名、不知道 ICP 备案可以查主办单位 |

## 2. 产品定位

**一个“只收官网”的开放目录 + 网址真伪鉴别工具。**

四条原则，决定了这个项目能否被信任：

1. **只收官网**：不收下载站、代理商、聚合页、镜像站。
2. **不卖排名**：永远没有竞价、广告位、付费收录。这是和搜索引擎最本质的区别。
3. **每一条都可溯源**：收录依据（ICP 备案主体、官方渠道声明等）公开可查。
4. **开放纠错**：任何人都能提交收录、纠错和举报，修改历史公开（Git 记录）。

## 3. 核心功能

| 功能 | 说明 | MVP 状态 |
| --- | --- | --- |
| 智能搜索 | 支持全称、简称、别名、拼音全拼、首字母（`zsyh` → 招商银行），自动忽略“官网/下载/入口”等后缀 | ✅ |
| 分类浏览 | 政务、教育考试、银行、运营商、出行、电商、软件下载等 | ✅ |
| 网址鉴别 | 粘贴一个网址，判断：✅ 已收录官网 / 🚨 疑似仿冒（包含官方品牌词、与官方域名只差 1~2 个字符）/ ⚠️ 未收录 | ✅ |
| 官网详情页 | 每个官网一个独立页面：官方地址、所有官方域名、别名、防骗提示、纠错入口 | ✅ |
| 收录申请 / 纠错 | GitHub Issue 表单，要求填写官方依据 | ✅ |
| 失效巡检 | 定期访问所有官网，发现打不开或跳转到未登记域名时报警 | ✅ |
| 浏览器插件 | 在百度 / 必应搜索结果中给真官网打 ✅ 标记、给仿冒站打 🚨 标记 | 规划中 |
| 小程序 / App | 移动端搜索和鉴别 | 规划中 |
| 开放 API | `GET /api/check?url=` 供其他产品接入鉴别能力 | 规划中 |

> 其中**浏览器插件**价值最大：用户不用改变习惯，照样用百度，只是结果里真官网被标出来了。

## 4. 怎样判定“这是官网”

这是整个项目的核心壁垒。采用**多源交叉验证**，至少满足一条硬证据：

**硬证据（任一即可）**

- **ICP 备案主体一致**：在 [工信部备案系统](https://beian.miit.gov.cn) 查询域名，主办单位就是该企业/机构。政府网站看 `.gov.cn` 与网站标识码。
- **官方渠道自证**：官方 App、已认证公众号/微博、营业执照、上市公司公告、政府部门网站里给出的链接。
- **HTTPS 证书**：OV/EV 证书中的组织名称与主体一致。

**辅助信号**

- 域名注册时间长（WHOIS）、与品牌高度相关。
- 国家企业信用信息公示系统中登记的网址。
- 行业权威名录：金融监管总局的持牌机构名单、教育部高校名单、政府网站名录等。

后续可引入**可信等级**：A（硬证据 ≥ 2）/ B（硬证据 1）/ C（仅辅助信号，显示提示）。

## 5. 数据模型

每个分类一个 YAML 文件：`data/sites/<分类id>.yaml`。

```yaml
- id: 12306                  # 必填，小写字母/数字/连字符，全局唯一，也是详情页 URL
  name: 中国铁路12306          # 必填，正式名称
  url: https://www.12306.cn  # 必填，官网首页，不允许带推广参数
  description: 中国国家铁路集团官方购票网站   # 必填
  aliases: [12306, 火车票, 高铁票]           # 可选，用户常用的叫法
  domains: [example.com]     # 可选，其他官方域名（用于网址鉴别）
  note: 唯一官方售票网站……      # 可选，防骗提示
  icp: 京ICP备xxxx号           # 可选，ICP 备案号
```

为什么用 YAML + Git 而不是数据库：

- 每次修改都是一个 Pull Request，**自带审核流程和完整历史**，谁改了什么一清二楚。
- 贡献门槛低，GitHub 网页上就能直接改。
- 数据本身就是开源资产，别人可以复用。

数据量到几千条之前，这种方式都完全够用。

## 6. 技术架构

### 阶段一：纯静态站（当前实现）

```
data/*.yaml ──► scripts/validate.js ──► scripts/build.js ──► dist/（纯静态 HTML）
   ▲              字段/重复/URL 校验         │ 首页 + 每个官网详情页
   │                                         │ sites.json 搜索索引（含拼音）
 PR / Issue                                   │ sitemap.xml / robots.txt
                                              ▼
                                GitHub Pages / 国内 CDN / 对象存储
```

- **零后端**：搜索在浏览器里完成，几千条数据的索引只有几百 KB，速度快、成本几乎为 0、抗压能力强。
- **构建时生成拼音**（`pinyin-pro`），前端无需加载拼音库。
- **CI**：每个 PR 自动校验数据并跑测试；合并到 `main` 自动部署。
- **巡检**：每周自动访问所有官网，发现失效或被跳转到未登记域名就出报告。

### 阶段二：动态服务（数据量上万、需要运营后台时）

- 后端：Node.js（Fastify/NestJS）或 Go + PostgreSQL。
- 搜索：Meilisearch / Elasticsearch（带拼音分词插件），支持错别字容错。
- 管理后台：收录审核工作流、多人复核、审核记录留痕。
- 自动核验爬虫：自动抓取 ICP 备案信息、证书组织名、WHOIS，给审核员预填证据。
- 仿冒监测：订阅新注册域名与证书透明度日志（CT Log），发现含品牌词的可疑域名主动预警。

### 阶段三：生态

- 浏览器插件（Chrome / Edge / 360 / QQ 浏览器）：在搜索结果页标注官网与仿冒站。
- 微信小程序：国内移动端主要入口。
- 开放 API：给安全软件、企业内网、反诈宣传等场景使用。

## 7. 数据冷启动

先覆盖“最常被搜错”的 500 个官网，优先级：

1. **高风险类**：银行、支付、政务（社保、个税、交管）、考试报名、火车票机票——被仿冒会直接造成财产损失。
2. **高频软件下载**：微信、QQ、WPS、各种驱动与工具——下载站捆绑重灾区。
3. **热门品牌**：手机、家电、电商。

数据来源：搜索引擎热搜里带“官网”的词、各行业权威名录、用户提交。

## 8. 让用户能搜到我们（也是在百度上）

讽刺的是，这个项目本身也要解决“被搜到”的问题：

- 每个官网生成独立详情页，标题形如 **“12306官网_12306官方网站入口”**，精准匹配用户搜索词。
- 生成 `sitemap.xml`，并在百度搜索资源平台、必应站长工具提交和主动推送。
- **在中国大陆提供服务需要 ICP 备案**，并建议使用境内服务器/CDN，否则访问慢且难以被百度收录。
- 内容干净、无广告、加载快，本身就是搜索引擎偏好的页面。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| 恶意提交假官网 | 必须提供官方依据；PR 需维护者审核；高风险类（金融/政务）双人复核 |
| 官网换域名 / 失效 | 定期巡检 + 用户纠错；跳转到未登记域名时人工复核 |
| 本站被仿冒或被劫持 | 全站 HTTPS + HSTS；数据开源可对照；域名简单好记 |
| 法律风险 | 只提供链接和公开信息，不使用对方商标做误导；接受权利人更正请求 |
| 可持续性 | 不卖排名；可以接受捐赠、提供付费 API/企业服务、与反诈宣传机构合作 |
