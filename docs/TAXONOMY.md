# 分类、标签与站点资料

目录保留稳定的记录 ID、原有一级分类（现扩展为 12 个，教育考试与区域机构分离）及原有来源记录。中文展示与机构拆分见 [中文整理说明](LOCALIZATION.md)。二级分类与主题标签由 `scripts/lib/taxonomy.js` 的 `rules-v1` 在加载时统一生成；不修改来源原文，也不提高核验状态。

软件按描述、名称和既有标签匹配开发、浏览、安全、设计、影音、办公、沟通、游戏、系统等用途。一条记录可有多个主题标签；主分类按规则顺序取第一个匹配。无法判断的记录归入“其他软件”。教育记录仅按名称及别名匹配职业教育、大学学院、学校、研究机构；专业方向作为参考标签。名称规则会有误分，不能据此确认办学类型、专业资质或软件能力，欢迎提交更正。

`data/profiles.json` 保存上游明确列出的资料，按记录 ID 关联。来源标识、首页和采集日期必须与目录一致；不一致会阻止构建，避免更新地址后沿用旧资料。来源字段只允许规定白名单，无法通过资料文件授予 verified 状态。

| 字段 | 来源与含义 |
| --- | --- |
| established | ROR 成立年份，缺失则不推测 |
| locations | ROR/GeoNames 的城市、行政区和国家；Hipo 明确列出的省州 |
| organization_types | ROR 注册机构类型，与细分检索分类不同 |
| name_languages | ROR 名称标签的语言，不是网站支持语言 |
| source_updated | ROR 注册资料最近修改日期，不是网站连接检测日期 |
| package_platforms | 本次 Cask 软件包的平台，不代表产品全部支持平台 |
| cask_languages | Cask 明确列出的软件包语言选项，不是网站语言 |

首页主机名、协议和记录编号从目录已有字段推导。HTTPS 不等于官网身份确认。未知主体、具体服务入口、站点语言和连接检测结果在详情页的“还需要补充什么”中列出，不自动猜测邮箱、备案号、下载网址或网站可用性。

## 重放补充过程

```sh
node scripts/enrich-profiles.js /path/to/source-directory
npm run validate
npm test
npm run audit:data
```

源目录需含 `homebrew-casks.json`、`universities.json`、`ror-v2.13/v2.13-2026-09-22-ror-data.json`。脚本核对 3 个固定 SHA-256 后才读取字段；所有检查通过后写入资料文件。此次使用既有批次的同一快照，没有新造记录或重新标记核验日期。升级来源快照时须同时审阅并修改脚本的文件名和哈希，重新生成元数据。

ROR 字段遵循 CC0，GeoNames 地理资料遵循 CC-BY-4.0；Homebrew Cask 和 Hipo 分别遵循 BSD-2-Clause 与 MIT。详情保留来源引用及 GeoNames 归属，许可证随导出数据分发。

## 网页使用

名称、别名、拼音、标签、英文城市名可以参与检索。分类、细分目录、地区、标签、来源和核验状态可组合筛选，支持名称排序、分页、紧凑列表及一键重置。详情标签与分类链接可回到带筛选条件的目录。

目录过滤链接只接受规定参数；输入框的搜索文字与粘贴地址不会写入地址栏、历史或本地存储。候选记录仍需要先查看资料，不自动跳转未经核对的地址；可主动复制待核对地址。
